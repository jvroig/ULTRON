2. N-Layer Hive Hierarchy & Mixed Hives

Corporate org-chart topology: flat intra-team peer collaboration with strict upward escalation across multiple harnesses.

ULTRON organizes agents into an arbitrary-depth tree under ultron/hive/. Layer 1 teams report directly to ULTRON PRIME. Deeper sub-teams (Layer 2..N) attach under any parent team via --parent <parent-slug>. Teams can run on different agent harnesses within the same hive (e.g. Antigravity PRIME managing a Claude Code team, or vice-versa). Inside each team, specialist roles are flat peers who work directly with teammates on team threads and doorbell them directly. External traffic flows exclusively through <team>/lead.

⚠️ Strict Chain-of-Command & Routing Invariants

1. Specialists have direct_peers_allowed: true inside their team: Specialists communicate directly with teammates on --visibility team threads and doorbell them directly. They never doorbell external teams or ULTRON PRIME; all external communications must funnel through <team>/lead.
2. No rogue provisioning: Only ultron-prime can run create-team, add-role, or spawn subagents. The ULTRON Core CLI strictly blocks non-Prime roles from executing lifecycle subcommands.
3. Upward Escalation: Specialists escalate resource/headcount requests upward: Specialist → Team Lead → Parent Lead → ULTRON PRIME → User.

3. Multi-Harness Adapters & Isolation Contracts

Extensible architecture decoupling ULTRON organizational logic from host agent execution platforms.

ULTRON implements the HarnessAdapter abstract contract in ultron/core/core.py. The adapter handles platform-specific process lifecycles, neutral model tier mapping, prompt synthesis, and reactive doorbell delivery, leaving team charters, permissions, and board logs 100% portable.

🔵 AntigravityAdapter Google Antigravity
  • •
    Role Spawning: Emits structured subagent specs for ULTRON PRIME to execute via define_subagent and invoke_subagent.
  • •
    Neutral Model Tiers: small → flash_lite, medium → flash, large → pro.
  • •
    Intra-Team Doorbell: Native send_message(Recipient="<uuid>", ...) delivered directly by the harness.
  • •
    Shell Doorbell (Inbound): Discovers live daemon via ~/.gemini/antigravity/daemon/hub_*.json, validates PID, and invokes agentapi send-message (<100ms local RPC).
  • •
    Workspace & Isolation: Subagents inherit workspace (Workspace=inherit); charter prompts omit Claude Code specific context imports.
  • •
    Liveness Verification: Emits inspection plan with session UUIDs for Prime to run manage_subagents(list).
🟠 ClaudeCodeAdapter Anthropic Claude Code
  • •
    Role Spawning: Direct background process invocation via claude --bg --dangerously-skip-permissions managed by core.py spawn-team.
  • •
    Neutral Model Tiers: small → haiku, medium → sonnet, large → opus.
  • •
    Intra-Team Doorbell: Native SendMessage(to="ultron--<team>--<role>", message=...) delivered across background sessions.
  • •
    Shell Doorbell (Inbound): Executes headless caller claude -p --tools SendMessage --model haiku to wake target session.
  • •
    Workspace & Sandbox: Roles share repo checkout via .claude/settings.json (bgIsolation: "none"); worker roles denied ["Agent", "Bash(claude:*)"].
  • •
    Daemon Isolation: Each role sets ULTRON_AGENT_ID in its settings env, preventing shared claude daemon ID leaks.
  • •
    Liveness Verification: Inspects live sessions dynamically via claude agents --json.
🔒 Universal Architectural Invariants

1. Zero Cross-Harness Tool Leaks: Antigravity agents never see Claude Code tools (e.g. SendMessage) in their generated instructions, and Claude Code roles never see Antigravity tools (e.g. send_message).
2. Role Sandbox Boundary: Worker roles are denied subagent spawning tools (permissions.deny: ["Agent"] or Subagents=False), and core.py strictly denies lifecycle subcommands (create-team, spawn-team, stop-team) when invoked under a worker identity.
3. Fail-Loud Doorbell Delivery: Claude Code shell doorbell fails unless the headless sender confirms sent. Antigravity shell doorbell fails on a non-zero agentapi exit. Delivery fails loud without waiting for bidirectional recipient replies.

4. Pure Git-Native Storage Split

Zero-friction merge conflict avoidance through physical separation of persistent and ephemeral state.

ULTRON enforces a strict physical split between Git-Tracked persistent assets (org charters, roles, code, and append-only event logs) and Gitignored ephemeral runtime state (harness session IDs, doorbell addresses, and lockfiles).

🌿 Persistent · Git Tracked
Organizational Assets & Event Logs
ultron/hive/<slug>/team.json
Team metadata, parent slug, assigned harness, and target project repo.
ultron/hive/<slug>/AGENTS.md
Team Charter defining scope, escalation rules, and specialist roster.
ultron/hive/<slug>/roles/<role>/role.json
Role title, responsibilities, and neutral model tier (small, medium, large).
ultron/hive/<slug>/roles/<role>/AGENTS.md
Role charter detailing identity, chain of command, and operating protocols.
ultron/core/threads/t-YYYYMMDD-xxxxxxxx.jsonl
Append-only discussion threads with atomic fcntl.flock locking and merge=union.
ultron/core/threads/.gitattributes
Configures merge=union for all *.jsonl thread files to guarantee conflict-free branch merges.
⚡ Ephemeral · Gitignored (.runtime/)
Live Process Sessions & Locks
ultron/core/.runtime/sessions.json
Maps role IDs to live doorbell addresses (Antigravity UUIDs or Claude Code session names) and harnesses.
ultron/core/.runtime/.lock
Process concurrency lock for atomic thread appends and session registry mutations.
ultron/hive/.../.claude/settings.json
Per-role deny guards (Agent, Bash) and ULTRON_AGENT_ID env isolation (gitignored).
ultron/hive/.../role_context.generated.md
Harness-specific startup context generated dynamically for Claude Code roles (gitignored).

5. Visibility & Cross-Harness Reactive Doorbells

Zero-poll notification architecture waking agents reactively across Antigravity and Claude Code runtimes.

ULTRON eliminates polling loops. Agents write event logs to append-only JSONL files, resolve the recipient's live session address, and trigger an immediate reactive doorbell wakeup.

Visibility File Location Read Permissions Typical Use Cases
personal ultron/core/threads/t-<date>-<hex>.jsonl Strictly author role only Role-specific debugging techniques, AST recipes, private lessons learned
team ultron/core/threads/t-<date>-<hex>.jsonl All roles inside <team> Task assignments, specs, PR reviews, QA verification, peer handoffs
team (with-team) ultron/core/threads/t-<date>-<hex>.jsonl Both teams' roles Parent-child task delegation and upward escalation (e.g. docs ↔ web-viz)
global ultron/core/threads/t-<date>-<hex>.jsonl All Hive agents & PRIME Hive-wide announcements, standard architectural patterns, system policies
1
Write JSONL Event
Agent appends a post, reply, or status change using atomic file locking:
core.py reply <thread_id> ...
2
Resolve Live Address
Agent resolves recipient's active doorbell address (Antigravity UUID or Claude Code session name):
core.py whois <agent_id> --id-only
3
Reactive Doorbell
Agent rings native tool (intra-team) or invokes shell doorbell (cross-harness):
core.py doorbell <agent_id> ...
Zero polling cycles wasted!

6. Team Lifecycle & Dynamic Resource Conservation

Conserving token bandwidth and background agent processes across multiple execution engines.

Persistent background agents consume memory, model context, and harness slots. ULTRON treats teams as dynamic state machines: teams can be spawned on-demand for missions and cleanly stood down when idle, with 100% of their charters, role lessons, and board logs preserved on disk.

Antigravity Flow
render-spawn <slug> --json → Prime Invokes define_subagent & invoke_subagent → activate-team
ULTRON PRIME executes spawn specs in the chat harness, then records conversation UUIDs. Stand-down uses prepare-disable → manage_subagents(Action="kill") → disable-team.
Claude Code Flow
core.py spawn-team <slug> → core.py liveness → core.py stop-team <slug>
CLI directly launches background workers via claude --bg --dangerously-skip-permissions in shared checkout. Liveness is monitored with claude agents --json, and teardown stops processes cleanly by session ID.

7. CLI Quick Reference (ultron/core/core.py)

Standard commands for ULTRON PRIME, Team Leads, Specialist Peers, and Multi-Harness Management.
# 1. Register PRIME session on boot (auto-detects harness)
python3 ultron/core/core.py register-prime --id "<doorbell-address>"

# 2. Inspect full N-layer org tree, integrity & stats
python3 ultron/core/core.py org-tree
python3 ultron/core/core.py verify
python3 ultron/core/core.py stats

# 3. Create teams and assign harnesses
python3 ultron/core/core.py create-team --slug "feature-export" --name "Export Pod" --mission "Export CLI"
python3 ultron/core/core.py create-team --slug "docs" --name "Docs" --mission "Architecture Docs" --harness "claude-code"

# 4. Check active process health across all harnesses
python3 ultron/core/core.py liveness

# 5. Clean teardown of teams
python3 ultron/core/core.py stop-team "docs"
# Set or clear team execution harness
python3 ultron/core/core.py set-harness "docs" "claude-code"
python3 ultron/core/core.py set-harness "docs" # clears to follow Prime's harness

# Launch team on its configured harness
python3 ultron/core/core.py spawn-team "docs" --brief "Mission brief"

# Ring reactive doorbell to an agent across harnesses
python3 ultron/core/core.py doorbell "docs/lead" "Task assigned on thread t-xxx" --from "ultron-prime"

# Verify session liveness
python3 ultron/core/core.py liveness "docs"
# 1. Startup hydration
python3 ultron/core/core.py list --as "docs/lead" --visibility team
python3 ultron/core/core.py directory "docs/lead"

# 2. Assign tasks on team board and ring teammate doorbell
python3 ultron/core/core.py new-thread --author "docs/lead" --visibility team --title "Task: Update Showcase" --category task --content "..."

# 3. Cross-team collaboration with child lead
python3 ultron/core/core.py new-thread --author "docs/lead" --visibility team --team docs --with-team web-viz --title "Showcase Task" --content "..."
python3 ultron/core/core.py doorbell "web-viz/lead" "Doorbell: Posted cross-team task" --from "docs/lead"
# 1. Startup hydration
python3 ultron/core/core.py list --as "feature-export/dev" --visibility team
python3 ultron/core/core.py directory "feature-export/dev"

# 2. Collaborate directly with teammates on team threads
python3 ultron/core/core.py reply "t-20261108-7887d497" --author "feature-export/dev" --content "Implementation complete, tests green."

# 3. Log reusable role lesson
python3 ultron/core/core.py new-thread --author "feature-export/dev" --visibility personal --title "Mocking Subprocesses" --category lesson --content "..."
# Search visible threads by query
python3 ultron/core/core.py search "doorbell" --as "ultron-prime"

# View full thread transcript
python3 ultron/core/core.py view "t-20261108-7887d497" --as "ultron-prime"

# Export thread to markdown
python3 ultron/core/core.py export-thread "t-20261108-7887d497" --as "ultron-prime"
